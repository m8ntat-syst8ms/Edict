01 / The product

Protection without a second workflow.

The platform integrates once. Each payment carries its promise, acceptance criteria and permitted outcomes. Both parties consent inside the payment flow; Edict runs in the background and appears only when something needs attention.

01

Commit the promise

The payment signs plain-language terms, objective checks, deadlines and possible outcomes.

02

Observe delivery

Connectors turn funding, delivery and evidence into one canonical, replay-safe event stream.

03

Resolve exceptions

Deterministic checks go first. Independent AI judges handle ambiguity; human review remains a policy toggle.

04

Settle, without custody

A customer-owned contract verifies the signed result. Edict can relay proof, but cannot redirect funds.

03 / Architecture

One runtime. Separate trust boundaries.

Edict coordinates evidence and decisions. It is deliberately unable to satisfy the contract’s execution quorum, hold a customer key, or choose a payout address.

Customer

Owns the settlement boundary

A keyless, immutable contract holds the payment under the customer’s approved configuration.

Protect

Observes and orchestrates

The hosted runtime schedules deadlines, verifies signed evidence, runs adjudication and publishes canonical events.

Judges

Produce independently verifiable decisions

Multiple model providers run two party-order orientations. Proof and confidence gates exclude unverified votes.

Contract

Revalidates every settlement

Challenge windows, exact outcomes, nonces and independent execution signatures are checked on-chain.

Intents

Moves value across chains

NEAR Intents supplies wallet authentication and cross-chain liquidity; the Edict contract remains the protection state machine.

04 / Integration

Protection should be a payment primitive.

A rail or marketplace configures its settlement boundary once, then registers each protected payment as part of the transaction it already creates. No separate Edict account, case form or custody handoff is required.

import { createEdict } from '@edict/sdk';
import { ProtectionRuntimeHttpClient } from '@edict/protection-runtime';
const edict = createEdict({ mode: 'live', settlement });
const protect = new ProtectionRuntimeHttpClient({ baseUrl, apiToken });
const payment = await edict.protectPayment(input);
await protect.protect(payment, { profile: edict.profile, intents });
